# Fengtai CMS server integration

The current `/admin` page is a local-first content manager. It is useful before a backend exists, but it is not a production authentication system:

- Products and categories are saved in the browser under `fengtai-catalog-v1`.
- Uploaded images are stored as browser Data URLs, so they are limited by browser storage and are not shared between devices.
- The default local password is `admin123`. Set `VITE_ADMIN_PASSWORD` during local testing, but do not treat a Vite environment variable as production authentication because it is shipped to the browser.

## Recommended production architecture

Keep the React admin screens and replace the storage implementation behind `CatalogContext` with three server capabilities:

1. Authentication: Supabase Auth, Auth.js, or a server session with an `httpOnly` cookie.
2. Database: PostgreSQL/Supabase tables for `categories` and `products`.
3. Media: Supabase Storage, Vercel Blob, or Cloudinary. Store only the returned public or signed URL in `products.image`.

## Minimal database schema

```sql
create table categories (
  id text primary key,
  group_name text not null check (group_name in ('ready-stock', 'custom-weaving')),
  title_zh text not null,
  title_en text not null,
  description_zh text not null default '',
  description_en text not null default '',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table products (
  id bigint generated by default as identity primary key,
  slug text unique not null,
  image_url text not null,
  group_name text not null check (group_name in ('ready-stock', 'custom-weaving')),
  subcategory text not null references categories(id),
  name_zh text not null,
  name_en text not null,
  category_zh text not null default '',
  category_en text not null default '',
  summary_zh text not null default '',
  summary_en text not null default '',
  specs_zh jsonb not null default '[]'::jsonb,
  specs_en jsonb not null default '[]'::jsonb,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

Import the JSON downloaded from the Data & Server tab as the initial seed. Map `image` to `image_url`; the current seed images that start with `/images/` can be copied into `public/images/products`, while Data URLs should be uploaded to object storage first.

## API contract

The frontend only needs these operations. The existing form fields already match the payload shape closely.

```text
POST   /api/admin/login
POST   /api/admin/logout
GET    /api/catalog
POST   /api/admin/products
PATCH  /api/admin/products/:id
DELETE /api/admin/products/:id
POST   /api/admin/categories
PATCH  /api/admin/categories/:id
DELETE /api/admin/categories/:id
POST   /api/admin/media              -> { url }
```

Return the same catalog shape as `src/types/catalog.ts` from `GET /api/catalog`. Validate names, slugs, category references, image MIME types, and maximum upload size on the server. Do not trust the browser's local validation.

## Frontend migration steps

1. Add an API-backed repository with `getCatalog`, `saveProduct`, `saveCategory`, and `uploadImage` methods.
2. Load the catalog in `CatalogProvider` from `GET /api/catalog` after the admin/public app starts.
3. Change the save callbacks in `AdminPage.tsx` to call the repository, then refresh the catalog from the API.
4. Replace `readImageFile` Data URL storage with a multipart upload to `/api/admin/media` and save the returned URL.
5. Remove the local password gate and use the server's authenticated session. Protect every `/api/admin/*` endpoint with the same session and an admin role check.
6. Keep JSON export/import as a backup and migration tool, but do not use it as the production data store.

For a Vercel deployment, the lowest-operations path is Vercel + Supabase: Vercel hosts the React app and API routes, Supabase provides Auth, Postgres, and Storage. The same interface also works with a separate Node/Express or NestJS server; only the repository and authentication wiring changes.
